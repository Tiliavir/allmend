# ADR-20261109: Pages (mini wiki)

Status: Accepted

## Decision
- Users create Markdown pages in the UI (stored in the database). Rendering with
  `goldmark` (GFM tables, task lists), raw HTML disabled, unsafe link schemes
  stripped.
- Per page: who may read and who may edit (everyone with module access, or
  selected accounts).
- Edits use optimistic locking (`version`); a stale save is rejected and shows
  both versions, never overwrites.
- Task list items can be ticked in the view. A tick changes only that line: the
  request carries page version and line text; if the page changed meanwhile the
  line is located by its text, if ambiguous the user gets a notice.
- Mermaid code blocks are rendered client-side by vendored `mermaid.min.js`
  (stored gzipped, ~1.6 MB), loaded only on pages that contain one. Those
  pages allow inline `<style>` in their CSP (Mermaid styles its SVG that
  way); `script-src` stays `'self'`.
- Every save keeps a revision; any revision can be restored. Deleting a page
  only hides it; content and revisions stay in the database.
- A page the account may not read answers 404, also for admins.
- Network documentation and the shopping list are pages.

## Why
One general feature covers docs, checklists and future shared notes (stated).
